# Деплой: Railway (сервер + база) и Vercel (клиент)

Схема: **браузер → Vercel (React) → Railway (Node API) → PostgreSQL (Railway)**.
Названия кнопок в панелях хостингов иногда меняются — ищите по смыслу.

## 0. Подготовка

1. Загрузите проект в **приватный** репозиторий GitHub. Файл `server/.env` в репозиторий попадать не должен (он в `.gitignore`).
2. Придумайте секреты и сохраните их в менеджере паролей:
   - `JWT_SECRET` — команда `openssl rand -hex 32` (или любая длинная случайная строка);
   - `ADMIN_PASSWORD` — надёжный пароль админа (не `admin123`).

## 1. Сервер и база на Railway

1. railway.com → **New Project → Deploy from GitHub repo** → выберите репозиторий.
2. В настройках сервиса: **Settings → Root Directory = `server`**.
3. **Settings → Deploy → Start Command:** `npm run start:prod`
   (он сам применит миграции базы, а затем запустит сервер).
4. В проекте нажмите **New → Database → Add PostgreSQL**.
5. В сервисе сервера откройте **Variables** и добавьте:

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | ссылка на переменную базы: `${{Postgres.DATABASE_URL}}` (имя сервиса базы может отличаться) |
   | `JWT_SECRET` | ваш секрет из шага 0 |
   | `NODE_ENV` | `production` |
   | `ADMIN_EMAIL` | email админа |
   | `ADMIN_PASSWORD` | пароль админа |
   | `CLIENT_URL` | адрес клиента на Vercel (заполните после шага 2) |
   | `STREAK_UTC_OFFSET` | `5` (Казахстан) |

6. **Settings → Networking → Generate Domain** — получите адрес вида `https://xxx.up.railway.app`.
7. Откройте `https://xxx.up.railway.app/health` — должно быть `{"status":"ok",...}`.

### Первичное наполнение базы (один раз)

Нужно создать админа, значки и 25 уроков. Запустите seed **с вашего компьютера**, указав внешний адрес базы:

1. В сервисе PostgreSQL откройте **Connect / Variables** и скопируйте **публичный** адрес (`DATABASE_PUBLIC_URL`). Внутренний `*.railway.internal` с компьютера недоступен.
2. В папке `server`:
   ```bash
   npm install
   DATABASE_URL="<публичный адрес>" ADMIN_EMAIL="вы@пример.com" ADMIN_PASSWORD="ваш пароль" SEED_DEMO=false NODE_ENV=production npm run prisma:seed
   ```
   `SEED_DEMO=false` — без демо-родителей и демо-детей. Для показа покупателю/садику демо можно оставить (уберите эту переменную).
3. Не оставляйте seed в Start Command: он перезаписывает программу уроков.

## 2. Клиент на Vercel

1. vercel.com → **Add New → Project** → тот же репозиторий.
2. **Root Directory = `client`**. Framework подхватится как Vite (`npm run build`, папка `dist`).
3. **Environment Variables:** `VITE_API_URL` = адрес сервера Railway из шага 1.6, **без** слеша в конце и **без** `/api`.
   Например: `https://xxx.up.railway.app`
4. **Deploy.** Файл `client/vercel.json` уже настроен, чтобы обновление страницы не давало 404.
5. Скопируйте адрес сайта Vercel и вставьте его в `CLIENT_URL` на Railway (сервер перезапустится сам).

> `VITE_API_URL` «вшивается» при сборке. Если поменяли — нужен **Redeploy** клиента.

## 3. Проверка после деплоя

- [ ] Сайт открывается, переключаются язык и тема.
- [ ] Регистрация родителя → добавление ребёнка → прохождение урока (должны расти XP и серия дней).
- [ ] Вход админа → «Уроки» → видны 25 уроков.
- [ ] После обновления страницы (F5) на внутренней странице нет 404.

## 4. Частые проблемы

| Симптом | Причина |
|---|---|
| Сайт открывается, но вход/запросы не работают | Не задан или неверен `VITE_API_URL` (проверьте во вкладке Network браузера, куда идут запросы), после правки — Redeploy |
| Сервер падает: `JWT_SECRET не задан` | Добавьте `JWT_SECRET` в переменные Railway |
| `Can't reach database` / миграции не применяются | Неверный `DATABASE_URL`; на Railway используйте ссылку `${{Postgres.DATABASE_URL}}` |
| Seed: «Задайте ADMIN_PASSWORD» | В production seed требует `ADMIN_PASSWORD` |
| Слишком много попыток входа (429) | Сработала защита от подбора пароля (30 попыток за 15 минут с одного IP) |
| 404 при обновлении страницы | Vercel не видит `client/vercel.json` — проверьте Root Directory = `client` |

## 5. Перед реальными пользователями

- Свой домен: Vercel → Settings → Domains (затем обновите `CLIENT_URL` на Railway).
- Резервные копии базы: включите бэкапы PostgreSQL на Railway.
- Данные детей — персональные. Серверы Railway находятся за пределами Казахстана; если вы продаёте садикам в РК, уточните у юриста требования к хранению данных до подписания договоров.
- Платные тарифы: бесплатных лимитов хостингов может не хватить для продакшена.
